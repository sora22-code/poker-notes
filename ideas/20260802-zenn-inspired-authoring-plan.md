# poker-notes 記事執筆体験の要件定義・プラン (2026-08-02)

Zennのオンラインエディタ(zenn.dev/articles/{slug}/edit)と公式Markdown記法ガイドを、ログイン済みブラウザで実際に操作・参照して得た知見を基にした要件定義。

## 0. Zenn実機調査で確認できたこと

### エディタUX (zenn.dev/articles/{slug}/edit)
- **2ペイン構成**: 左Markdownエディタ / 右リアルタイムプレビュー、右下に「スクロール同期」トグル
- **自動保存**: 右上に「保存済み」バッジが常時表示。保存操作を意識させない
- **公開は別操作**: 「公開する」トグルが独立。執筆と公開が分離されている
- **公開設定パネル**: frontmatterを手書きさせず、UI化されている
  - アイキャッチ絵文字（ピッカーで変更）
  - トピック（5つまで）
  - カテゴリー（Tech / Idea の2択、選び方ガイドへのリンク付き）
  - 公開予約トグル
- **「+」ボタン → 埋め込みモーダル**: X/YouTube/Gist/CodePen/CodeSandbox/StackBlitz/Figma等を、記法を覚えなくてもフォームから挿入できる
- **入力補完**: `:`で絵文字補完、テキスト選択+URLペーストでリンク化

### 記法ガイドから
- Zenn独自ブロック: `:::message` / `:::message alert` / `:::details タイトル`（ネストは`::::`）
- コードブロック拡張: ` ```js:ファイル名 `、` ```diff js `、mermaid対応
- KaTeX数式（`$$`ブロック + `$`インライン）、脚注`[^1]`、URL単独行→リンクカード
- 思想: **「独自記法・オプションはポータビリティの観点で必要最低限に」「著者の負担を増やさない」**（公式コメントより）

### poker-notesへの示唆
Zennの本質は「執筆者が記法やメタデータの管理から解放され、本文に集中できる」こと。poker-notesはMDXの表現力で既にZennを超える部品(PokerTable/HandRangeChart/EquityCalculator/用語ホバー)を持っているが、**書くコストが高い**(Propsを手書き)。ギャップは「部品」ではなく「入力体験」にある。

## 1. 最重要要件: ハンド図ビジュアルエディタ（テーブル図の自動生成）

> 「自分や相手のポジションやポット額を入力すると自動でテーブルの図が作成され可視化される」

### 1.1 実装形態: `/tools/hand-editor` ページ（Reactアイランド1枚）

サイト内に公開ページとして置く（執筆者専用ツールだが、読者も局面図を作って遊べるためコンテンツとしても機能する）。

```
+--------------------------------+--------------------------------+
| 入力フォーム                     | ライブプレビュー                  |
|                                |                                |
| ストリート: [preflop|flop|...]   |     (PokerTableがリアルタイム      |
| ポット: [ 4 ] bb  [自動計算✓]    |      に再描画される)              |
| ボード: [Ah][7c][3d][ ][ ]      |                                |
|                                |                                |
| ▼ プレイヤー                     |                                |
| [✓] BTN  stack[97.5] bet[2.5]  |  +---------------------------+ |
|     [ ]Hero [✓]Active cards[  ] |  | <PokerTable               | |
| [✓] BB   stack[98]   bet[1]    |  |   street="preflop"        | |
|     [✓]Hero [ ]Active [Ac][Jd]  |  |   pot={4} ... />          | |
| [ ] UTG ...                    |  +---------------------------+ |
|                                |    [MDXをコピー] [リセット]      |
| キャプション: [____________]      |    [プリセット: BTNvsBB ▼]      |
+--------------------------------+--------------------------------+
```

### 1.2 機能要件

| # | 要件 | 詳細 |
|---|---|---|
| E-1 | ポジション選択 | UTG/HJ/CO/BTN/SB/BB(6-max)のON/OFF。9-maxは将来対応 |
| E-2 | プレイヤー属性 | stack / bet / isHero(排他) / isActive(排他) / folded / cards(カードピッカー) |
| E-3 | ボード入力 | カードピッカー(スート4色ボタン+ランク13ボタン)。テキスト入力(`Ah 7c 3d`)との両対応 |
| E-4 | **ポット自動計算** | ブラインド(0.5+1)+各プレイヤーのbet合計から自動算出。手動上書きも可 |
| E-5 | ライブプレビュー | 入力のたびに実物のPokerTableコンポーネントで即時再描画(Zennの2ペイン体験) |
| E-6 | **MDX出力** | 「MDXをコピー」で`<PokerTable client:visible ... />`スニペットをクリップボードへ。記事に貼るだけ |
| E-7 | バリデーション | カード重複(ボード/ホールカード間)、bet>stack、Hero複数指定を即時警告 |
| E-8 | プリセット | 「BTN vs BB シングルレイズポット」「3ベットポット」等の典型局面をワンクリック読込 |
| E-9 | URL共有 | 状態をURLクエリにエンコード(`?s=...`)。共有・ブックマーク・記事からのリンクが可能 |

既存の`lib/poker/types.ts`(PlayerSeat/Position/Street)とdeck.tsのバリデーション関数をそのまま再利用できるため、追加のドメインロジックはほぼ不要。**実装コストの大半はフォームUIのみ**。

### 1.3 発展: ActionLine・EquityCalculatorのスニペットも同時生成
同じエディタに「アクション履歴」タブ(ポジション+アクション+額の行を追加していく)と「エクイティ」タブ(ハンド/レンジ+ボード入力)を設け、記事で使う3部品すべてのMDXを1箇所で組み立てられるようにする。

## 2. Zenn風・記法の軽量化（書くコストの削減）

### 2.1 ディレクティブ記法の導入（remark-directive）

Zennの`:::message`と同じ感覚でポーカー部品を書けるようにする。Propsを覚えなくてよい。

```markdown
:::table{street=flop pot=9 board="Ah 7c 3d"}
BTN 95.5 bet:2 active
BB* 96 cards:"Ac Jd"
:::
```
→ ビルド時に`<PokerTable>`へ変換（`*`=Hero）。既存のremark-glossaryと同じパイプラインに`remark-directive`+変換プラグインを追加するだけで実現可能。

同様に:
- `:::range{title="BTNオープン"} raise: 22+, ATs+ :::` → HandRangeChart
- `:::equity{board="Ah 7c 3d"} AcJd vs QQ+, AK :::` → EquityCalculator
- `@[action](BTN raise 2.5, SB fold, BB call)` → ActionLine

**方針**: MDXコンポーネント直書きは引き続き有効（高度な用途向け）。ディレクティブは糖衣構文として共存。ハンド図エディタ(§1)のMDX出力もまずはコンポーネント形式で出し、ディレクティブ実装後に切替オプションを付ける。

### 2.2 記事scaffold

`npm run new:article` で対話式に slug/タイトル/カテゴリを聞き、frontmatter+テンプレ構成(状況設定→プリフロップ→…→学び)入りのMDXを生成。Zennの「フォームでfrontmatterを埋める」体験のCLI版。

## 3. 初学者への優しさ（読者体験）

| # | 施策 | 内容 |
|---|---|---|
| B-1 | 用語集ページ `/glossary` | 既存の`lib/glossary.ts`(36語)から自動生成。カテゴリ別一覧+ページ内検索。ホバー解説の「もっと知りたい」の受け皿 |
| B-2 | 難易度バッジ | frontmatterに`level: beginner\|intermediate\|advanced`を追加。ArticleCardと記事ヘッダに色分けバッジ表示。トップページで難易度フィルタ |
| B-3 | 前提知識ボックス | `:::prerequisite`ディレクティブ。「この記事はポジションの基礎を前提とします → [入門記事へ]」を記事冒頭に定型表示 |
| B-4 | ハンド記法の読み方カード | 「AJo」「22+」等の記法を初出時にホバー解説（glossaryにレンジ記法エントリを追加するだけで実現） |
| B-5 | 入門シリーズ記事 | 「ポジションとは」「ハンドレンジの読み方」「ポットオッズ入門」の3本。B-3の前提知識リンク先として機能させる |
| B-6 | 触って学べる計算機 | EquityCalculatorの`readonly=false`版を入門記事に配置し「AKoとQQ、どちらが強い？」等の演習付きで能動学習を促す |
| B-7 | 図の一貫性 | 全記事の局面図をPokerTable(§1エディタ産)に統一。同じ見た目の図が繰り返し出ることで読解コストが下がる |

## 4. Zennとの機能対応表（ギャップ分析）

| Zennの機能 | poker-notes現状 | プラン |
|---|---|---|
| 2ペインライブプレビュー | astro dev のHMR(保存時反映) | §1エディタで部品単位のライブ編集を提供。本文はHMRで十分 |
| 自動保存 | git管理(手動commit) | 現状維持(gitの方が履歴管理は強い) |
| frontmatter UI | 手書きYAML | §2.2 scaffoldで生成。手書き頻度を初回のみに |
| 埋め込みモーダル(+ボタン) | MDX手書き | **§1ハンド図エディタ(ポーカー版埋め込みモーダル)** |
| `:::message`等の軽量記法 | Astroコンポーネントimport | §2.1ディレクティブで同等の書き味に |
| 絵文字アイキャッチ | frontmatter `emoji` | 現状維持(OGP生成済み) |
| 公開予約 | なし | 不要(git push=公開のワークフロー) |
| KaTeX数式 | なし(記事3でコードブロック代用) | remark-math+rehype-katex追加(ポットオッズ計算式の表示品質向上) |
| mermaid | なし | 低優先(ポーカー記事での用途が薄い) |
| 脚注 | remark標準で対応済み | 現状維持 |

## 5. 実装フェーズ分割

| Phase | 内容 | 規模感 |
|---|---|---|
| **A** (必須要件) | `/tools/hand-editor`: フォーム+ライブPokerTable+ポット自動計算+MDXコピー+バリデーション (E-1〜E-7) | 中 |
| **B** | エディタ拡張: プリセット(E-8)+URL共有(E-9)+ActionLine/Equityタブ(§1.3) | 小〜中 |
| **C** | ディレクティブ記法(§2.1)+scaffold(§2.2)+KaTeX | 中 |
| **D** | 初学者施策: /glossaryページ+難易度バッジ+前提知識ボックス(B-1〜B-4) | 小 |
| **E** | 入門シリーズ3本執筆(B-5, B-6) | コンテンツ作業 |

推奨順: **A → D → E → B → C**（必須要件を最初に、次に読者体験、記法改善は書き手が自分だけのうちは後回しでよい）

## 6. 非スコープ（今回やらないと決めたこと）

- Zennそのものへの投稿自動化・クロス投稿（Zennの利用規約と体験の分離のため。poker-notesはZennと競合しない独自ドメインのメディア）
- ブラウザ上での本文Markdown編集・保存（git+ローカルエディタの方がバックアップ・差分管理に優れる。Zenn自身もGitHub連携を推奨している）
- ハンドヒストリー(PokerStars形式等)の自動パース → 将来検討。フォーマットが多様でメンテコストが高い
